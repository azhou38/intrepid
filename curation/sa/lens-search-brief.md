# SA run: brief for every destination photo searcher (Lens)

Repo: /Users/alexzhou/Developer/mobile-wellington (run commands from there). Role: .claude/agents/image-searcher.md. Rules: IMAGES.md ("Every photo", "The four checks", "Headers", "Why visit photos", "When Commons has no suitable photo").

Input: `curation/sa/lens/dest-<K>/task.json`: slots `dest:<id>:header` and `dest:<id>:why<N>` for NEW South Australian destinations (not in src/data yet, so the gather script cannot run; you are the search). Each slot's `context` has the destination name, category, centre, description and the exact need (a why-visit photo must show that reason). Existing candidates in `candidates.json` are all "unresolved: place not found"; overwrite that file.

For each slot find up to 6 candidates, best first, from Commons (region-qualified queries, e.g. "Port Lincoln, South Australia"; the place's Commons category; geosearch near the centre; prefer Featured/Quality/Valued). Header: >= 1500 px wide, aspect 0.6-2.0, the place itself in its landscape/cityscape; why-visit: >= 1280 px, landscape, shows exactly that reason. Current colour photos only, no maps/drawings/aerials for headers/archive scans/logos/signs, no person or animal as the main focus, not a file used for a different destination (check `grep -F "<file>" src/data/imageOverrides.ts src/data/destinations.ts`). Within this run's destinations the same file may serve a header, a why-visit photo and a spot of one destination, never two destinations. Check each file's page (description, categories, coordinates) so it is the right place; vague names (Burra, Quorn, Robe, Goolwa, Beachport) must be proven local. Verify real pixel width from the Commons imageinfo API. Wikimedia 429: wait 30/60/120 s. Fetch with `npx tsx scripts/curation/fetch.ts <url>` or the API directly with a User-Agent.
When Commons has nothing usable for a slot, try Openverse (`scripts/openverse-search.py`), then official/tourism photos (flag as `official: true`, permission risk), as IMAGES.md says; for a source that blocks scripts list it under `needs_browser`.

Output: `curation/sa/lens/dest-<K>/candidates.json` = `{ "<slot>": [ { "file": "<Commons file name without File:>" | "url": "...", "page": "<file page URL>", "width": n, "height": n, "licence": "...", "by": "...", "why": "<what it shows, one line>" } ], "_unresolved": { "<slot>": ["..."] } }`. A slot with nothing: empty list and a line in your report. Do not judge or rank beyond ordering. Validate it parses. Final message at most 8 lines: counts per group, every slot with fewer than 2 candidates, every unresolved or needs_browser item.
