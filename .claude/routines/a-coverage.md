# Routine: Pipeline A — coverage

Run by the scheduled cloud routine "Intrepid coverage". Rules: `COVERAGE.md` (read "Finding what is missing" first: coverage runs per region, judges inclusion blind to placement, and reports fairness). Conventions: `PIPELINES.md`. Do not merge anything.

1. `npm ci --ignore-scripts`; take the first region marked `NO PASS` from `npx tsx scripts/curation-backlog.ts --country <CC>` (or the region the routine's prompt names). One region per run and per pull request.
2. In `curation/<branch>/region-<id>/`, in this order (job prompts in `.claude/routines/jobs/`):
   - `coverage-enumerator` → `candidates.json` (`jobA-region.md`): the whole region from sources, then `npx tsx scripts/curation/score-candidates.ts` for views, coordinates and existing-spot matches; no destination information.
   - `npx tsx scripts/curation/score-filter.ts --region-dir <dir>`: a script keeps the strong candidates and rejects the unambiguous ones (events, civic buildings, vehicles, memorials, no source and no interest) and writes `marginal.json` (the only candidates an agent reads), `auto-decided.json` (every script decision, for the owner's report) and `audit.json` (a sample of the script's decisions).
   - `coverage-judge` → `judged.json` and `audited.json` (`jobA-judge.md`): ONE agent judges the marginal band (the skeptic's source check built in) and blind re-decides the audit sample.
   - `npx tsx scripts/curation/merge-verdicts.ts --region-dir <dir>` writes `verdicts.json` and `skeptic.json`. It exits 2 if the judge disagrees with more than 1 in 10 of the audited script decisions: then the script's rules do not fit this region, and `coverage-judge` runs on EVERY candidate (the full path) before the run is accepted.
   - `coverage-proposer` → `placement.json` and `fairness.json` (`jobA-place.md`): places what was kept, then writes the fairness report. Every placement entry carries its `category` (tier-spots.ts needs it).
3. Reject the run (no pull request; say why) if `fairness.json` shows a candidate scoring above the lowest-scoring kept spot left out without a concrete reason from "What qualifies", or if the benchmark in `COVERAGE.md` fails for this region.
4. Apply only what the judge or script kept and the proposer placed, per `WRITING.md` (ids never reused, standalone fields, names, coordinates from a source). Add every new standalone spot to its region in `scripts/coverage-regions.json`. New spots need a photo and facts: run Lens (`lens-triage.ts` → `photo-prove.py` → `image-searcher` + `image-judge` only for what the script cannot prove) and Quill (`tier-spots.ts`: simple spots get a bio only, the rest the full research chain); a standalone spot gets exactly the same photo search as a destination spot. Run `npx tsc --noEmit`, `npx tsx scripts/audit-spot-coordinates.ts --country <CC>`, `npx tsx scripts/check-destination-headers.ts`, `npx tsx scripts/photo-prefilter.ts`, `npx tsx scripts/build-image-manifest.ts`. One commit per destination touched, and one for the region's standalone spots.
5. One pull request through the REST API assigned to `azhou38`. Body: the fairness report first (inside/standalone split, strongest outsiders and what happened to each, lowest-scoring kept spots), then the evidence table (candidate, score, sources, verdict, placement, reason), the review list, and what could not be verified. Then the push notification.
